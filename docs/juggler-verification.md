# Juggler pull verification

Two trials are recorded here: the v0.2.7 migration candidate and the earlier v0.2.6 onboarding trial. The migration
candidate installed and upgraded successfully on native Linux x86-64, Linux ARM64, and macOS ARM64. The Linux x86-64
trial also ran in the pinned Homebrew container below.

## Migration candidate, 2026-11-03

Upstream [disabled its tap-push job](https://github.com/scode/juggler/pull/263/changes) before publishing
[juggler v0.2.7](https://github.com/scode/juggler/releases/tag/v0.2.7). The release includes the
[TLS fix](https://github.com/scode/juggler/pull/261/changes). Archives, checksums, and the release-side Ruby artifact
are still published, but the upstream workflow no longer writes a formula here.

The candidate activates juggler in live `pull.toml` and replaces the upstream-pushed v0.2.6 formula with the first
pull-generated formula. Explicit `update --dry-run`, `update juggler --tag v0.2.7`, and `regenerate --check` passed. All
four archive hashes match the release's `sha256.sum`; live `pull.toml` records them. The historical example config
remains at v0.2.6 for reproducing the onboarding trial.

| Formula                         | SHA-256                                                            |
| ------------------------------- | ------------------------------------------------------------------ |
| Candidate v0.2.7 (pull)         | `635e6915f71809fc5981f25f50389faeaaf720a4419ae86e9827987591acce96` |
| Previous v0.2.6 (upstream push) | `9b496ac66911eed7359321370cab52bc2487c6149cd877e8516c29516a70904e` |

The baseline was the formula upstream actually pushed, not a regenerated v0.2.6 formula. It has no test block, so the
acceptance script skips `brew test` for the baseline and requires it for the candidate. On the same pinned image and
environment recorded below, `scripts/formula-upgrade-test.sh` passed these steps:

| Operation                                                           | Result |
| ------------------------------------------------------------------- | ------ |
| Fresh v0.2.7 install, identity against live config, functional test | Passed |
| Uninstall, then pushed v0.2.6 install and executable identity       | Passed |
| Upgrade from pushed v0.2.6 to v0.2.7, identity, functional test     | Passed |

The v0.2.7 Linux x86-64 archive SHA-256 is `97fde94fa6253059741a42a79816f757446913ea678090d9fd8bb0e218068c8c`; the
installed executable matched `902ca765588ea3ee19c8e6c0bf322f0666d2c62c61d7a93e84642383d4d47897` after both fresh install
and upgrade. The baseline's executable matched `de7aec0bb818d0a088ebe0a4db205f0ba8a08465a53fe4a9670817d0d94a2159`.

Both v0.2.7 Linux binaries still require glibc symbols through 2.34 and list `libgcc_s.so.1`, `libm.so.6`, `libc.so.6`,
and their architecture's loader as dynamic dependencies. They have no dynamic OpenSSL or libdbus dependency.

The migration PR's
[Formula upgrade run 41761843977](https://github.com/scode/homebrew-dist-tap/actions/runs/41761843977) passed the same
acceptance script on all three native runners:

| Platform     | Fresh v0.2.7 install, identity, functional test | Pushed v0.2.6 install, identity | Upgrade to v0.2.7, identity, functional test |
| ------------ | ----------------------------------------------- | ------------------------------- | -------------------------------------------- |
| Linux x86-64 | Passed                                          | Passed                          | Passed                                       |
| Linux ARM64  | Passed                                          | Passed                          | Passed                                       |
| macOS ARM64  | Passed                                          | Passed                          | Passed                                       |

Runner images track current Homebrew and OS versions; the container trial is the pinned environment. Intel macOS is
archive-validation coverage only. Neither the TUI nor authenticated Google Tasks sync was exercised.

To reproduce the migration trial, generate the candidate from live `pull.toml`, obtain the old formula from the tap's
pre-migration base commit, and use the [pinned container recipe](treeward-verification.md#repeat-the-trial) with
`juggler`, the candidate, live config, old formula, and `0.2.6` as the acceptance script's five arguments.

## Tooling trial, 2026-11-03

Verified on 2026-11-03: the juggler updater validated all four v0.2.6 archives, generated a scratch formula, and passed
a native Linux x86-64 Homebrew install and functional test. At this point juggler was still push-managed; the trial did
not activate its live `pull.toml` entry or change `Formula/juggler.rb`.

### Candidate identity

Use the commit introducing this report as the tooling revision for reproduction. The tested formula was uncommitted
scratch output generated by that implementation, not the existing formula under `Formula/`. Its SHA-256 is
`c1fa44598f1267aa08ee2cd064fba5310e7561fa486cd204b73668a1c375c893`.

The inspected release is [juggler v0.2.6](https://github.com/scode/juggler/releases/tag/v0.2.6).
[The example config](../examples/juggler.toml) records all four archive hashes, each matching the release's published
`sha256.sum`. Regeneration, checked regeneration, explicit `update --dry-run`, and a repeated explicit update passed
against those bytes. The generated formula kept the digest above.

This historical release established the packaging contract. It predates the upstream TLS fix; the migration candidate
above uses the patched v0.2.7 release.

### Archive and runtime contract

The four target triples are `aarch64-apple-darwin`, `x86_64-apple-darwin`, `aarch64-unknown-linux-gnu`, and
`x86_64-unknown-linux-gnu`. Each asset is `juggler-<target>.tar.xz` under the selected GitHub release and contains
exactly one `juggler-<target>/` directory with the executable `juggler`, `README.md`, `CHANGELOG.md`, and the MIT
`LICENSE`. The formula installs the executable and those documents. Separate release-side updater executables and Ruby
formula artifacts are not consumed.

Upstream's
[packaging inspection](https://github.com/scode/juggler/blob/794c74c7892f6fd4c43f15c8e3b69b7f7aca681e/docs/homebrew-publishing.md)
records Linux glibc symbol requirements through 2.34, system framework/library dependencies on macOS, and no additional
Homebrew library dependency. It records binary minimum macOS versions of 11.0 for ARM64 and 10.12 for Intel; these are
metadata, not runtime coverage on those systems. Interactive editing needs an external editor. Google Tasks sync needs
OAuth credentials, macOS Keychain or a Linux D-Bus Secret Service, and network access. The formula test needs none of
these facilities.

The installed-tool test loads a TOML TODO fixture with unsupported format version 2 and requires the version rejection.
It then changes the fixture to version 1 and requires the missing OAuth client ID error, with identical file content and
no archive created. Explicit blank credential flags override inherited credentials, stopping before keychain or network
access. `File.write` replaces the fixture because Homebrew's `Pathname#write` refuses overwrites. This establishes local
store parsing and credential validation; it does not exercise the TUI or authenticated Google Tasks sync.

### Environment and results

The disposable container used the ordinary Homebrew image user, no publishing credentials, and read-only mounts of the
generated formula, example config, and acceptance script. Automatic Homebrew updates and analytics were disabled.

| Component           | Observed value                                                            |
| ------------------- | ------------------------------------------------------------------------- |
| Native architecture | x86_64                                                                    |
| OS                  | Ubuntu 24.04.4 LTS                                                        |
| glibc               | 2.39                                                                      |
| Homebrew            | 6.0.22                                                                    |
| Image               | `ghcr.io/homebrew/ubuntu24.04`                                            |
| Image digest        | `sha256:613f2f524c4d1fb8fe37dbe7a5581392c89e7865bac725bab0d8e24309ae6d7c` |

`scripts/formula-upgrade-test.sh` passed a fresh v0.2.6 install, archive identity against the example config, installed
executable identity, and `brew test`. The installed executable SHA-256 was
`de7aec0bb818d0a088ebe0a4db205f0ba8a08465a53fe4a9670817d0d94a2159`. No upgrade was attempted: the live formula already
selects v0.2.6. Linux ARM64 and both macOS archives were downloaded and validated, not installed or executed. This
result does not establish compatibility with older glibc releases.

To reproduce, generate into scratch with `cargo xtask --config examples/juggler.toml --output-dir scratch/Formula
regenerate`, then repeat with `regenerate --check`. Follow the
[pinned container recipe](treeward-verification.md#repeat-the-trial), mounting that formula directory and the example
config read-only. Run the acceptance script with three arguments: `juggler /inputs/juggler.rb /candidate.toml`. Three
arguments test a fresh install without claiming an upgrade.
